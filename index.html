開啟多人同步，需要做的一次性設定（約 5 分鐘）

GitHub Pages 本身是靜態網站，沒辦法自己記住多人的訂單，所以多人同步需要一個免費的即時資料庫。本頁已內建 Firebase Realtime Database 的程式碼，只要填入設定就好：

  1. 到 Firebase Console 建立專案（免費 Spark 方案即可），新增一個網頁應用程式。
  2. 在左側選 Realtime Database → 建立資料庫，位置選亞洲區，初期規則可先設為測試模式（之後再依下方規則收緊）。
  3. 把 Firebase 給你的設定值，貼到本檔案最下方 FIREBASE_CONFIG 的位置，重新發佈後，所有人打開頁面就會自動進入同步模式，不需要登入。

建議的資料庫規則（只允許讀寫 rooms 底下的團購資料）：

{
"rules": {
"rooms": {
"$room": {
".read": true,
".write": true
}
}
}
}

注意：這個規則是「知道團購代碼就能讀寫」，適合朋友、同事間的臨時團購，不適合放機密資料。代碼請用不容易猜到的字串，例如 2026-10-27-office-8f3k。在設定完成之前，頁面會自動用本機模式運作，功能完全正常，只是訂單只存在自己的裝置上。

關於「每天自動更新」

星巴克官方沒有公開即時菜單 API，本頁因此採用每日機制：① 每天第一次開啟時，菜單更新日自動變成當天、今日推薦重新輪換；② 團購代碼預設就是當天日期，跨日自動開新團，不會把昨天的訂單混進今天；③ 要更換正式品項時，只要編輯本檔案內的 MENU 清單並重新發佈，訪客重新整理後即生效。
